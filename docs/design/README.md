一页可滚动的设计规范 + 两页真实数据布局稿。它**不是**可以直接上线的页面，而是用来定：

## 二、设计决策与理由

### 1. 为什么主色从 #1450D2 换成 #1D4E89

原来的 `hsl(221 83% 45%)` 实测是 `#1450D2` —— 一个很饱和的亮蓝，按钮上白字对比度 6.76:1。
饱和度高的蓝在中文教育类产品里读起来像"在线工具"，而填志愿场景需要的是"官方文件"的观感。
换成 `#1D4E89` 后饱和度从 83% 降到 71%、明度从 45% 降到 32%，白字对比度升到 8.39:1，
同时色相仍是蓝，与原有 5 个风险层不冲突。

### 2. 为什么靠边框而不是阴影分层

现有实现用 `--radius: 0.6rem` + 阴影堆叠。稿子改成 8px 圆角 + 1px 边框 + 极轻阴影
（`0 1px 2px rgba(15,23,42,.04)`）。理由：这是数据密集型界面，一屏有几十个数字，
投影会让层次变"软"，而政务类界面的信任感来自秩序（对齐、分隔、留白），不是拟物。

### 3. 为什么风险层颜色整体压暗

现有五个风险色是 `#DC2828 / #F97015 / #E7B008 / #0DA2E7 / #198653`，都很鲜艳。
稿子压到 `#B42318 / #C2410C / #A16207 / #0E7490 / #0F7B4F`，并配同色系浅底。
原因有两个：一是鲜艳的红黄蓝绿同时出现在一屏里会互相抢注意力，二是压暗后作为**文字色**
放在浅底上能达到 4.76–6.05:1 的对比度，而原来的亮色做不到。

色相顺序保持"红→橙→黄→青→绿"的单调递进，且每个徽标都带中文名 —— 颜色不是唯一信息载体。

### 4. 为什么 ACS 不做进度条

进度条天然被读成"完成度/概率"。产品铁律是 **ACS 是安全指数，不是录取概率**。
所以 ACS 只用「大号数字 + 小字 ACS」呈现，颜色跟随风险层，不加任何环形/条形填充。

同理，稿子里没有任何"录取几率 87%"式的表述。

### 5. 为什么推荐结果在宽屏用两列

单列铺满 1376px 时，每张卡片右侧有 400px 空白，信息密度过低 —— 一屏只看得到 4 张。
两列后一屏 6–8 张，且每张卡仍能容纳院校 / 城市 / 专业 / 3 个标签 / 4 个数据点。
1280 以下自动回落单列。

### 6. 为什么方案表格限宽 900px

10 列（序号/院校专业/选考/风险层/ACS/置信度/计划/学费/资格/锁定）在 1376px 下，
院校列会吸收掉三百多像素空白。限宽到 900 后列宽自然贴合内容。
这个宽度也是后续「导出 Excel / 打印」的参考版式。

### 7. 为什么占位文字用 ink-500 而不是更浅的灰

第一版用 `#94A3B8`，实测对比度只有 **2.56:1** —— 连 3:1 都不到。
填志愿的用户里有大量家长，字号偏小、对比度低的输入提示是真实障碍。
现在：

- **占位文字**用 `ink-500 #64748B`（4.76:1，达 AA）
- **ink-400 加深到 `#728297`**（3.92:1），并且**只用于图标、边框、禁用态**
  —— 这些属于非文本内容，3:1 即可达标

### 8. 为什么数字全部等宽

位次有 5–6 位数，ACS 有 1 位小数，学费有 4–5 位数。比例字体下同一列数字的个位对不齐，
扫读时会错行。全站数字统一 `font-variant-numeric: tabular-nums`。

### 9. 为什么筛选生效时提示常驻

现有实现是"拖拽被禁用"但用户不知道为什么。稿子把提示做成常驻的琥珀色条，
位置固定在筛选栏下方，并带「清除筛选」快捷入口 —— 用户需要**先知道原因**，而不是拖不动才发现。

### 10. 为什么方案已满用错误色而不是灰按钮

灰化按钮不解释任何东西，用户会当成 bug。稿子里「加入」在满额时给出明确的红色说明：
"加入后志愿数将超过目标 96 个（当前 96 个），请先删除或调整目标数量"。

## 六、未覆盖 / 需要你确认的点

1. **应用图标**：稿子里用纯色方块 + 「鲁」字占位。要更好的图标需要你给源文件（512×512 PNG 或 SVG），否则 P2 会用占位。
2. **字体**：现在只用系统字体。如果希望数字更精致，可以打包一款等宽数字字体（+2MB），但会偏离"政务风"的通用感 —— 我倾向不打包。
3. **健康分仪表**：稿子没画（属于 P5 的可视化范围）。如果你对它有具体想法（环形/半圆/分段条），现在说比 P5 时改更省事。
4. **响应式下限**：稿子按 1280–1440 设计。如果你会在更小的笔记本（1366×768）上用，需要我再补一版 1366 的检查 —— 目前 1280 无横向溢出，但两栏会偏窄。
