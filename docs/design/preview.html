一、设计原则

这套界面的用户是在做一个人生级别的决定，且往往伴随焦虑。设计目标不是"好看"，而是"敢信"。

数据优先

位次、ACS、计划数、学费是第一眼要看到的。装饰元素一律让位，不出现在数据周围。

弱阴影、强边框

用 1px 边框与留白分层，不用投影堆叠。政务类界面的"稳"来自秩序感，不是玻璃拟态。

风险必须能数出来

五个风险层永远同时给出颜色、中文名、数量。不用颜色单独承载信息，色盲用户也能读。

不制造确定性错觉

ACS 是安全指数不是概率。界面任何位置都不出现"录取几率 87%"这类表述，也不把它画成进度条。

二、色板

主色由原来的 hsl(221 83% 45%)（实测 #1450D2，饱和度过高、按钮白字仅 6.76:1）换成更沉的 #1D4E89：降低饱和换取可信感，按钮白字对比度升到 8.39:1。

筛选生效时的拖拽禁用提示

筛选生效时不能调整顺序（拖拽与上下移已禁用），请清除筛选后再排序，否则隐藏的志愿会一起位移。清除筛选

这条提示必须常驻在筛选栏下方，而不是只在拖拽时才出现 —— 用户需要先知道"为什么拖不动"。

方案已满时的加入提示

加入后志愿数将超过目标 96 个（当前 96 个），请先删除或调整目标数量。

用错误色而不是灰化按钮 —— 灰化不解释原因，用户会以为是 bug。

八、空状态 / 加载 / 错误

当前筛选下没有志愿
试试取消「只看 985」，或把省份放宽到全部。候选池共 18,924 条。

骨架屏代替"正在读取…"文字。形状要贴近真实内容，否则切换时会跳。

推荐生成失败
优化器在 30 秒内未找到可行解。可能是「最低安全数量」设得过高，或锁定的志愿与目标数量冲突。

错误信息必须说清"发生了什么 + 可能的原因 + 下一步怎么做"，不要只抛一行异常文本。

适配与可访问性要求

  • 设计宽度 1440，最小支持 1280（两栏各不低于 560px，再窄则上下堆叠）
  • 所有可点区域 ≥ 24×24；表单控件高度 36
  • 焦点环统一 0 0 0 3px rgba(29,78,137,.18)，键盘 Tab 可见
  • 风险层不靠颜色单独表达，永远带中文名
  • 尊重 prefers-reduced-motion：关闭骨架动画与过渡
  • 数字用等宽，避免位次位数不同导致错列
  • 不做深色模式（本版范围外）
