系统当前运行在**真实数据**上：山东 2022–2025 普通类常规批第 1 次志愿本科计划。

```
院校        1,153 所（覆盖 32 个省级行政区）
专业序列    25,280
招生计划    73,198 条     2022: 16,848 / 2023: 17,737 / 2024: 18,891 / 2025: 19,722
历史录取    72,885 条     含最低位次
一分一段    1,033 行      2022–2025 普通类一段
选科规则集  69 种
快照        SD-2022-2025   quality=THIRD_PARTY   is_demo=false
```

> **数据来源声明**：源文件来自第三方整理包，**不是山东省教育招生考试院官方发布**。
> 系统据此标记 `source_documents.quality = 'THIRD_PARTY'`（而非 `OFFICIAL`），
> `/api/v1/meta/dataset` 会返回明确警告。第三方来源会通过 Confidence 的数据源质量项
> （权重 0.15）让 ACS 略保守。**真实填报前请以官方《填报志愿指南》核对。**

> **源文件不随仓库分发**：这批工作簿来自商业整理包，不可再分发，且体积较大。
> 本仓库只包含读取它们的代码。要用真实数据，需要自行准备源文件并按下文指定路径。

## 一、指定源文件位置

代码**从不硬编码本机路径**。三种方式任选：

```bash
# 1. 命令行参数（推荐）
python -m app.ingestion.etl_shandong --data-root /path/to/高考志愿

# 2. 环境变量
export GAOKAO_DATA_ROOT=/path/to/高考志愿
python -m app.ingestion.etl_shandong

# 3. 不指定则回落到开发机上使用的默认位置（其他机器上通常不存在）
```

所有 `scripts/*.py` 探测脚本同样接受 `--data-root`。

## 二、导入

```bash
cd backend
export DATABASE_URL=postgresql+psycopg://gaokao:gaokao_dev_only@127.0.0.1:5432/gaokao

# 演练：只读源文件、打印规模与解析覆盖率，不写库
python -m app.ingestion.etl_shandong

# 正式载入（实测约 9 分钟）
python -m app.ingestion.etl_shandong --write

# 清理 DEMO 演示数据，只保留真实数据
python -m app.ingestion.purge_demo --write

# 端到端验证：跑一次流水线并导出 docs/real-run.json
python -m app.ingestion.snapshot_run 60000 PHY,CHM,BIO
python ../scripts/analyse_real_run.py
```

导入是**幂等**的：重复执行只更新不重复。`--reset` 会在写入前清理上一次的真实数据快照。

## 三、选科要求解析（覆盖率 99.99%）

真实文件的 `选科要求` 列共 21 种取值，解析器覆盖 **79,274 / 79,279 行**
（未解析的 5 行是源文件本身的空单元格）。逐年：

| 年份 | 样本 | 覆盖率 |
|---|---|---|
| 2022 | 18,276 | 100.00% |
| 2023 | 19,220 | 99.97%（5 个空格） |
| 2024 | 20,336 | 100.00% |
| 2025 | 21,447 | 100.00% |
| 官方格式文件（2025 详细版） | 21,425 | 100.00% |

解析出的真实形态分布：

| 行数 | 原文 | DNF 组结构 | 含义 |
|---|---|---|---|
| 25,247 | 物理和化学 | `[[PHY,CHM]]` | 两门都要 |
| 24,083 | 不限 | `[]` | 无限制 |
| 17,001 | 物理 | `[[PHY]]` | 单科 |
| 4,014 | 物/化/生(3选1) | `[[PHY],[CHM],[BIO]]` | **三选一** |
| 1,623 | 物理 或 化学 | `[[PHY],[CHM]]` | 二选一 |
| … | 其余 16 种 | | |

**三类写法都必须处理，漏任何一类都会出错**：

1. **全名 + 「和」/「或」** —— `物理和化学`、`物理 或 化学`
2. **单字简称 + 斜杠/顿号** —— `物/化/生(3选1)`、`物化生(3科必选)`
3. **尾随数量约束** —— `(N科必选)` 表示全选，`(N选1)` 表示选一

> **第 3 类不能当装饰剥掉。** `物/化/生(3选1)` 里的 `/` 若按分隔符推断会被读成 AND，
> 得出「三门都要」—— 与原文完全相反，会让大量本可报考的志愿被判为不可报。

**无法确定性解析时**返回 `None` → 规则集 `is_authoritative=False` → Rule Engine 输出
`UNKNOWN`（不猜测为可报）。真实数据里只会走到 `物化生(3选2)` 与 `(物理或历史)且化学`
这两类，且并未出现。

验证：`python scripts/verify_subject_rules.py --data-root <路径>`

## 四、一分一段表口径（重要）

一分一段表同时含「普通类一段」与「普通类二段」。**只载入一段**，
`exam_year_stats.ranked_candidates` 取一段达线人数：

| 年份 | 一段控制线 | 达线人数（= 位次百分位分母） |
|---|---|---|
| 2022 | 437 | 301,611 |
| 2023 | 443 | 308,701 |
| 2024 | 444 | 318,935 |
| 2025 | 441 | **333,469** |

若误用一段+二段总人数（2025 年为 681,127），考生位次百分位会被压低一半，ACS 整体失真。
2025 年的 333,469 与官方公布「333469 人超本科线」一致，可作佐证。

## 五、跨年对齐用名称，不用官方代码

这是实测结论，与直觉相反，记录下来避免以后改错：

| 跨年对齐方式 | 2023→2024 | 2024→2025 | 三年连续可对齐 |
|---|---|---|---|
| 官方代码（院校代码+专业代码） | 57.6% | 59.1% | 8,343 |
| **名称（院校基名+专业基名）** | 83.5% | **84.3%** | **13,790** |

代码相同的 12,418 对里只有 65.4% 名称也相同 —— **代码会被复用或重编**，
用它当身份比名称更不稳定。所以 `program_series.series_key` 用
`院校代码|院校基名|专业基名`，官方代码作为属性保存在
`admission_plans.special_requirements` 的「专业代码 X」中。

验证：`python scripts/probe_series_identity.py --data-root <路径>`

## 七、用接口增量导入

`POST /api/v1/ingestion/*` 用于导入新的官方文件，全部默认 `dry_run=true`。

| 接口 | 用途 | 必需列 |
|---|---|---|
| `/ingestion/score-rank` | 一分一段表 | `exam_year`, `score`, `same_score_count`, `cumulative_rank` |
| `/ingestion/plans` | 当年招生计划 | `university_name`, `plan_name`, `plan_count` |
| `/ingestion/outcomes` | 历年投档/录取结果 | `university_name`, `plan_name`, `exam_year`, `min_rank` |
| `GET /ingestion/templates` | CSV 表头模板 | — |

- **有一条 error 就整个文件不写入**，不存在"导一半"的状态，错误报告带源文件行号
- 列名兼容中英文别名，编码自动识别 UTF-8 / GBK，分隔符自动嗅探
- 幂等：同一份文件重复上传只更新不重复，改文件名也认得出来（按内容 SHA-256）
- 每次导入写入 `source_documents`（含 SHA-256、发布单位、来源 URL）
